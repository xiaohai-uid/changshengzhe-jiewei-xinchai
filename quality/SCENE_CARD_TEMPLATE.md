# SCENE CARD TEMPLATE V2

> 作用：把后台规划翻译成角色世界内部的场景。正文只能从 Scene Card 生长，不能直接把 Rolling Outline 展开成小说。

## 使用规则

每章起草前先写一个简短 Scene Card。它属于作者层工作纸，不进入正文。

Scene Card 禁止出现：CHxxx、FP-xxx、CHAR-xxx、Canon、Ledger、State Diff、KNOWS/UNKNOWN、必须推进、章尾目标等后台语言。

Scene Card 的文字要像“如果把摄像机放进这个世界，人物今天会经历什么”，而不是作者任务清单。

## Card 八问

### 1. 场景开始时，谁想要什么？
只写人物当前能感知的目标。

优先写具体可争取的东西，而不只写“活下来 / 不暴露”。例如：保住一个岗位、争到一次处置机会、拿到某种材料、确认一个人的可信程度、把某人从一种处置里移出来。

### 2. 什么现实阻力阻止他？
必须是现场存在的制度、人物、身体限制、时间压力或信息不足。

### 3. 他手里真正知道什么？
只列人物能凭正文证据知道的内容；不把作者真相塞进去。

### 4. 他必须在哪个信息不足处做选择？
优先让人物在规则未完全揭明前选择，而不是先看足所有样本再精准通关。

### 5. 如果选择成功，他实际会得到什么？
必须落在世界内部可触摸的变化：
- 身体/能力；
- 药材/食物/器物/资源；
- 身份或分类；
- 行动范围/时间/权限；
- 某个人对他的需要或债；
- 一个真实被改变的结果；
- 一条可用于下一步行动的信息。

如果答案只有“知道更多”，必须确认近期没有连续只给信息奖励。

### 6. 选择带来什么双向后果？
至少包含：解决一个眼前问题 + 新增一个风险/债/暴露面/损耗。

但新增代价不能为了证明“世界有成本”而机械把第5项全部取消。

### 7. 场景结束后，他比开始时多了什么，又少了什么？
分别写清楚。

如果连续几个场景答案都是“多了秘密；少了健康/安全/自由”，先停下来重构，不进入 WRITE。

### 8. 新问题怎样从这次变化里长出来？
优先让新冲突来自本场获得：

获得身份 → 多了职责与监视；
获得能力 → 多了资源需求和暴露风险；
获得关系筹码 → 被卷进更深交易。

避免无因重置：刚解决一轮检查，下一场只换个房间重新检查同一问题。

## 配角检查

本场重要配角分别回答：如果主角不在，他们本来会做什么？如果答不出来，先补人物动机再写。

配角自己的行动必须能与主角发生碰撞，而不是等主角来触发剧情。

## 样本限制

制度/测试场景中，普通样本最多重点展示 1—2 个。其余通过环境、队伍变化、记录动作或简短连续叙事带过。禁止为了说明规则把所有情况逐项演示。

## 场景密度

一个场景优先围绕一个主要选择展开。若需要同时解释制度、推进三条伏笔、引入新人、完成反转，应拆分到后续场景/章节。

## Scene Ready 硬门

进入 WRITE 前检查：

- Scene Card 是否脱离 Rolling Outline 后仍像一个能自然发生的场景？
- 主角是否有现场欲望，而不是只承担作者的“发现任务”？
- 成功是否有现实收益？
- 代价是否存在但未机械归零收益？
- 配角不依赖主角也会行动？
- 结束状态是否真正改变？

任一关键项答不出来：Scene Card = FAIL，不进入正文。
