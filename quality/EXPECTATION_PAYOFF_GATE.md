# EXPECTATION / PAYOFF GATE V1

> 目标：在连续性与小说质感之外，防止长篇长期陷入“压迫 → 发现更多秘密 → 新压迫”，保证读者能持续感到主角正在获得可累积的主动权。
>
> 本 Gate 是质量/商业阅读体验工具，不是世界 Canon，也不是机械爽点公式。

## 0. 基本原则

本书不追求无脑打脸或固定爆点频率。

采用：

**期待 → 兑现 → 升级**

- 期待：读者知道陈缺当前具体在争取什么。
- 兑现：前面承诺的东西真正落地，并留下现实残余。
- 升级：新冲突从已经获得的东西自然长出来，而不是把主角重置到原点。

核心约束：

> **代价可以污染爽点，但不能习惯性归零爽点。**

> **信息可以是奖励，但不能长期成为唯一奖励。**

## 1. EXPECTATION CHECK

交稿前必须能明确回答：

1. 本章/当前小周期，读者最希望陈缺“得到、做到或改变”的具体事情是什么？
2. 这个期待来自此前正文，而不是作者临时宣布的吗？
3. 期待是否不仅仅是“别死 / 别暴露 / 看看下一关是什么”？
4. 如果本章不负责兑现，它是否至少明显推进了兑现条件，而不是只增加一个新谜题？

### REWRITE 风险

- 连续章节只有负目标：不死、不被抓、不被发现、不被送药房。
- 章尾长期只有“又出现一个新秘密/新检查/新危险”。
- 主角知道更多，但读者仍不知道这些知识最终能帮他争到什么。

## 2. PAYOFF CHECK

本章若承担兑现功能，至少检查以下资产之一是否发生真实变化：

- **ABILITY**：能力变强、变稳、出现新的具体用途；
- **RESOURCE**：获得可使用的药材、食物、钱、器物、修炼材料或资源渠道；
- **STATUS**：身份、分类、职位、组织价值发生上升；
- **FREEDOM**：行动范围、选择权、时间、通行/工作权限增加；
- **LEVERAGE**：关系中的议价权、债、把柄、互相需要程度发生变化；
- **IMPACT**：主角第一次能真实改变制度/人物/局势的结果；
- **INFORMATION**：得到关键情报。

INFORMATION 可以单独成为一次重要奖励，但不能长期连续成为主奖励。

## 3. DURABILITY CHECK

获得不要求永久免费，但必须问：

1. 这个收益在章末还剩什么？
2. 新代价是否把收益完全抵消？
3. 如果收益消失，是否至少转化为另一项长期资产？
4. 最近两次重要兑现是否都出现“刚获得 → 立刻失去 → 回到原点”？

### 硬风险

连续两次重大获得都被同章或下一章几乎完整抹掉，默认 `REWRITE`，除非这是一个明确设计的重大失败 Arc，且失败本身永久改变人物/关系/世界状态。

## 4. AGENCY CHECK

陈缺的优势不是永远猜中，而是理解系统后逐渐能行动。

检查：

- 本章主要推进是否由陈缺的选择触发？
- 若他处于完全被动，本章是否有明确必要性，并在后续形成反制条件？
- 是否再次出现“看别人踩坑 → 完整理解 → 精准通过”？
- 是否只是换了道具，本质仍是“隐藏 → 对方误判 → 脱身”？

如果主角连续两章主要功能只是旁观、记录、猜测，第三章默认必须让他做一个会改变局面的选择，除非当前处于无法行动且这一无力本身是明确剧情事件。

## 5. REWARD VARIETY CHECK

检查最近约 3—5 个主要兑现：

- 是否全是信息？
- 是否全是境界升级？
- 是否全是别人震惊？
- 是否全是隐藏实力成功？
- 是否全是“免于惩罚”？

同类奖励连续重复时，优先转换奖励形态，而不是机械增加强度。

本书优先轮换：

**规则反制 / 职业价值 / 能力实践 / 资源获得 / 身份变化 / 关系议价 / 情绪释放 / 真相回收。**

## 6. COST CHECK

本书仍坚持“没有免费力量”。

成功至少可以带来一项成本：

- 身体损耗；
- 资源消耗；
- 暴露面；
- 责任；
- 被记录/控制；
- 关系债；
- 错误认知风险；
- 新敌意。

但成本设计必须回答：

> **陈缺付完这个成本以后，是否仍比场景开始多了一点什么？**

若答案长期为“没有，甚至更差”，商业阅读体验风险升高。

## 7. CONFLICT UPGRADE CHECK

兑现后产生的新问题优先满足：

- 因为获得新身份，所以承担新职责；
- 因为获得新能力，所以需要更多资源/暴露新特征；
- 因为获得议价权，所以进入更危险的交易；
- 因为知道规则，所以必须决定是否使用规则伤害别人。

避免：

- 刚拿到东西就被无因夺走；
- 同一种检查换个房间再做一遍；
- 上一章解决“会不会暴露”，下一章重新从零解决同一个“会不会暴露”。

## 8. READER QUESTION TYPE

每章标记当前主驱动力：

- `MYSTERY`：这到底是什么？
- `ACTION`：陈缺接下来会怎么做？
- `PAYOFF`：前面承诺的东西什么时候/如何兑现？
- `RELATIONSHIP`：两人的利益/信任会如何变化？
- `GROWTH`：能力/身份会如何升级？

本书允许 MYSTERY 很强，但不能长期只有 MYSTERY。

如果连续三章主驱动力都是“想知道更多答案”，而没有 ACTION / PAYOFF / GROWTH 的明显增强，默认商业节奏报警。

## 9. 禁止机械公式

以下不作为硬标准：

- 三章一小爆、五章一大爆；
- 每 2000—3000 字必须一个高潮；
- 每章必须打脸；
- 每章必须升级境界；
- 每章必须赢。

慢章、失败章、蓄压章都允许存在，但必须服务于清晰期待，并在合理周期内真实兑现。

## 10. 结论

结论只允许：

- `PASS`：期待明确，兑现/推进有效，收益与代价共同成立；
- `REWRITE`：长期负收益、纯信息、主动性不足、兑现被归零或奖励算法重复；
- `BLOCKED`：当前 Arc 的正向期待/阶段收益尚未设计清楚，不能用正文临时补。

**只有 Publication Gate + Expectation/Payoff Gate + Continuity Precommit 全部 PASS，Candidate 才可交用户。**
