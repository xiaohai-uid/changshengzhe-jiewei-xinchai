# CHAPTER GATE V6

> 每章依次通过：MACRO ALIGNMENT → PREWRITE → SCENE ISOLATION → WRITE → MIDWRITE → PUBLICATION GATE → EXPECTATION/PAYOFF GATE → PRECOMMIT → USER REVIEW → CANON PROMOTION → POSTCOMMIT。Candidate 与 Canon 严格分离。
>
> 同时服从 `quality/WORKFLOW_STATE_MACHINE.md`。任何缺失步骤一律 FAIL CLOSED，不得直接交稿。

## MACRO ALIGNMENT

写正文前必须回答：
1. 本章属于哪个 Arc？
2. 推进当前卷哪个核心问题？
3. 当前只允许推进到哪一层真相？
4. 是否推进长期人物弧，而非把配角当信息工具？
5. 当前短周期读者具体在等待什么正向兑现？
6. 如果删掉本章，Arc/卷结构与期待曲线损失什么？若几乎没有，重做章节合同。

## PREWRITE

1. **Canon Horizon**：确认从哪一章正式 Canon 起写。
2. **上一章因果**：最后实际发生的动作最自然导致什么？
3. **合同**：只保留 1—2 个核心事件。
4. **容量**：目标 3200—3600 字，硬区间 2800—4000 字。
5. **Timeline / State / Knowledge / Ability**：位置、身体、物品、能力、已知/未知无越权。
6. **FP/P/S**：只推进本场真正需要的项。
7. **Pattern**：检查最近五章高层胜利算法，不只看道具是否重复。
8. **Published Prose Anchor**：实际回读至少两段已发布高质量正文，校准段落和叙述质感。
9. **Expectation / Payoff**：明确本章是建立期待、推进兑现条件、部分兑现还是主要兑现；明确成功后会留下什么现实资产。
10. **Context Receipt**：登记实际读取来源；关键源缺失则 BLOCKED。
11. **Workflow**：`quality/workflow/CHxxx_WORKFLOW.md` 已存在，且状态已合法推进到 LOADED / MACRO_ALIGNED。

## SCENE ISOLATION（硬门）

正文不得从 Rolling Outline 直接展开。

必须先按 `quality/SCENE_CARD_TEMPLATE.md` 生成角色世界内部 Scene Card，回答：
- 谁现在想要什么？
- 现场阻力是什么？
- 他真正知道什么？
- 哪个信息不足处必须做选择？
- 成功后实际得到什么？
- 选择解决什么，又新增什么代价？
- 结束后人物比开始时多了什么、少了什么？
- 新问题怎样从这次变化里长出来？

Scene Card 若仍出现 CHxxx、FP-xxx、Canon、KNOWS、必须推进、章尾目标等后台标签，FAIL。

如果场景结构仍是“样本A/B/C逐项展示→主角看懂答案→精准通关”，FAIL，除非该结构此前长期未用且本章有实质误判/代价。

如果 Scene Card 的收益只有“知道更多”，而近期已经连续以信息为主奖励，必须先通过 Expectation/Payoff 预检再进入 WRITE。

## MIDWRITE CAPACITY CHECK

正文约 3000—3300 字检查：
- 是否还有两个以上关键节点？有则顺延。
- 是否开始用对话/摘要赶设定？有则回退。
- 是否强迫人物为大纲改变行为？有则改大纲。
- 本章主要选择是否已经产生后果？产生后可以自然收章，不额外加第二个高潮。
- 是否为了补“爽点”突然加入未铺垫的打脸、能力或资源？有则删除并回到场景因果。

## PUBLICATION GATE

必须读取并逐项执行 `quality/PUBLICATION_GATE.md`。

以下任一出现即 REWRITE，不得交稿：
- 后台语言泄漏（第三章/上一章/CHxxx/Canon 等）；
- 连续三个以上无必要的一句式叙述段；
- 大量短词独段制造假节奏；
- 提纲逐项扩写；
- 最近五章高层破局算法重复；
- 陈缺判断正确且几乎无代价；
- 重要配角若主角不在场就“无事可做”；
- 同类“这不能证明/至少说明”解释腔反复出现；
- 章尾靠神秘人突然抛一句信息硬切，而非本章因果后果。

Publication Gate 结论只允许 PASS / REWRITE / BLOCKED。

## EXPECTATION / PAYOFF GATE（硬门）

Publication PASS 后，必须读取并执行 `quality/EXPECTATION_PAYOFF_GATE.md`。

至少回答：
- 当前读者在等什么具体兑现？
- 本章是否真正推进/兑现，而不是只加谜题？
- 陈缺获得了什么可持续资产或现实变化？
- 代价是否把收益几乎完整抹掉？
- 最近奖励是否长期只有信息？
- 陈缺是否正在从“理解规则”转向“利用规则/获得主动权”？
- 新冲突是否从本次获得自然升级？

以下为重点 REWRITE 信号：
- 连续高压而正向目标仍只有“不死/不暴露”；
- 重大获得连续出现“同章/下一章立即清零”；
- 连续多章主要奖励都是新秘密；
- 陈缺连续只观察、解释、被分流，没有会改变局势的选择；
- 为满足爽感而强塞无逻辑打脸。

Expectation/Payoff Gate 结论只允许 PASS / REWRITE / BLOCKED。

## PRECOMMIT

### 连续性
- Candidate 是否与正式正文、Kernel、Chapter Ledger 冲突？
- 状态变化是否关闭旧 temporal fact 并新增新 fact，而非覆盖历史？
- UNKNOWN/SUSPECTS 是否误升为事实？
- 能力来源、进入方式、代价和受益者是否一致？

### 小说质量
- 正文是否 2800—4000 字，常规约 3200—3600？
- 是否集中完成 1—2 个核心事件？
- 是否有认知/关系/风险/能力/身份/资源/现实影响至少一项实质变化？
- 成功是否带来新的成本、暴露面或债？
- 成本是否合理且没有机械取消全部成长？
- 配角是否按自身利益行动？
- 常规段落是否自然承载动作/观察/心理，而非短句瀑布？
- 是否像同一本已发布小说，而不是管理系统生成的剧情报告？

### Reader Experience
- 本章读者最想知道/看到的主问题是什么？
- 驱动力主要是 MYSTERY / ACTION / PAYOFF / RELATIONSHIP / GROWTH 中哪一种？
- 问题是否发生变化而不是只多一条症状？
- 是否有情绪变化？
- 是否兑现至少一点？
- 章尾是否自然推出下一步？

Precommit 结论只允许 PASS / REWRITE / BLOCKED。

## USER REVIEW

只有以下三项全部 PASS，工作流才允许进入 `USER_REVIEW`，并向用户展示完整 Candidate：

- Publication Gate = PASS
- Expectation/Payoff Gate = PASS
- Continuity Precommit = PASS

任何一项未完成或非 PASS：禁止交稿。

用户否决/要求重写时，旧 Candidate 立即失去规划权威；其中新增姓名、编号、机制细节等不得被后续误当 Canon。

## CANON PROMOTION

用户明确确认后：
1. 正文固化。
2. Candidate Facts / Knowledge / Timeline / Relationship / FP-P-S 转 Canon。
3. 更新 Kernel temporal records。
4. 追加 Chapter Ledger + Chapter Record。
5. 重建 state/tracking 投影。
6. 更新 Narrative Pattern、Commercial Rhythm、Rolling Outline、Context Card。
7. 正文自然改变卷内因果时同步修订 Detail / ARC_MAP，不改过去迎合旧纲。
8. 写 Commit Receipt。
9. 全部通过才推进 `main` Canon Horizon。

失败：不推进 `main`。

## POSTCOMMIT

- 校验 Canon Horizon 与 Manuscript/Kernel/Ledger 一致。
- 每5章 Snapshot + Warm Memory compaction + Publication Pattern + Expectation/Payoff 曲线回顾。
- 每10章 Continuity + Narrative Pattern + Macro Drift Audit。
- Arc 结束生成 Arc Summary，并复盘阶段期待是否真正兑现，再重算下一 Arc。
- 卷末生成 Major Canon Version。
- Revision 必须执行 Change Impact Protocol，禁止静默修补。
