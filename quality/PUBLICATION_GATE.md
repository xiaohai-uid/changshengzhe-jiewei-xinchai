# PUBLICATION GATE V5

> 目标：在连续性之外，判断正文是否像真实可发布的长篇小说。
>
> **进入条件：Post-Draft Audit = PASS，且candidate_revision_id一致。**
>
> Publication PASS只代表小说质感/场景写法/最终章节名通过；仍必须继续通过Expectation/Payoff、Continuity与Final Delivery。

## 1. Scene First

正文不得直接从Rolling Outline展开。必须先经过Scene Card。

若Post-Draft的Outline Leakage Audit已经判定逐项扩写，本Gate不得通过句子润色“救活”结构问题，必须退回Scene Card。

## 2. 后台泄漏硬FAIL

正文出现以下内容默认FAIL：
- “第三章 / 上一章 / 前文 / 本章”等作者章节回指；
- CHxxx、FP-xxx、CHAR-xxx、Canon、Ledger、Snapshot、State Diff等仓库语言；
- 角色使用作者数据库标签思考。

要求Post-Draft Mechanical Lint给出扫描结果；本Gate复核语境。

## 3. 段落硬门

- 常规叙事段优先2—5句；
- 一句独段只用于真正需要停顿的死亡、反转、答案、极强动作或关键对话；
- 连续3个以上无必要一句式叙述段默认FAIL；
- 连续短词独段/大量空行制造速度感默认FAIL。

必须参考Post-Draft统计，不只凭印象。

## 4. 提纲扩写硬FAIL

若正文呈现：
- 样本A→结果、B→结果、C→结果、主角通关；
- 大纲节点按原顺序逐项出现；
- 新人物的背景/技能/信息恰好一次性服务所有章纲任务；
- 章尾只是把Outline问题换成小说句子；

默认FAIL。

普通样本只保留真正有戏剧价值的1—2个；章节必须由人物欲望、阻力、选择、后果推动。

## 5. 胜利算法检查

检查最近5章高层破局模型，而不只看道具。

以下换道具仍算重复：
- 看别人踩坑→完整规则→精准通过；
- 装弱/隐藏→对方误判→无代价脱身；
- 偷听内幕→答案→规避危险。

近期重复成为主解：REWRITE，除非结构发生明显变化并有误判/成本/新责任。

## 6. 正确也要付成本，但收益不能被此处强行清零

陈缺判断正确可以获得主动权，但成功后应新增至少一种合理成本：身体、记录、关系债、暴露、责任、资源消耗、错误认知风险。

成本是否把收益过度归零，由Expectation/Payoff Gate继续审查。

## 7. 配角主体性

重要配角必须能回答：

> 如果陈缺今天不在场，这个人自己会做什么？

正文中也应能看到这条独立行动痕迹。

赵石、韩鸦、顾长槐及关键知情者不得只负责展示症状、送情报、调组或递任务。

## 8. 推理语言

“这不能证明 / 这只能证明 / 至少说明 / 这不代表”等不可成为默认叙述模板。

谨慎优先行为化：压下猜测、暂不行动、保留退路、降低下注条件。

## 9. 对话

- 对话不能成为设定问答机；
- 角色不能为了方便读者解释自己本来不会解释的信息；
- 同一角色语言应符合身份、利益、回避习惯；
- 信息能通过动作/后果表现时，不强迫人物讲出来。

## 10. Anti-AI / Redundancy

复核Post-Draft发现：
- 短句瀑布；
- 动作→感知→解释三层重复；
- 场景已表达后主题再总结；
- “不是……而是……”/“他没有……只是……”连续复用；
- 万能情绪按钮；
- 像策划案标题的章尾。

命中明显模式：REWRITE。

## 11. Reader Experience

必须能回答：
1. 本章读者最想看到什么？
2. 问题是否真正变化？
3. 情绪是否发生变化？
4. 是否有小兑现或兑现条件明显前进？
5. 本章主要是在人物行动，还是叙述者替人物完成规划？
6. 最后300字是否来自现实后果？

## 12. Memory / Distinctiveness

读取 `quality/MEMORY_ANCHOR_SYSTEM.md` 与 `tracking/MEMORY_ANCHOR_LEDGER.md`，复核Post-Draft的MEM证据。

### 章节级不是“必须新增名场面”

允许：`NO NEW ANCHOR`。

但必须回答：

1. Scene Card第9问是什么？
2. 如果本章产生Anchor Candidate，它来自场面/人物/关系/物件本身，还是作者硬写的漂亮句子？
3. 若调用旧Anchor，它有没有增加新情绪、新关系、新信息或新含义？
4. 有没有为了让读者记住而机械重复原句、物件、口头禅或命题？
5. 隐去姓名后，关键人物的强对白/选择是否仍符合其独有关注点和利益？

### 强制反向检查

以下情况默认REWRITE：
- 人物突然说出与身份/当下利益无关的哲理金句；
- 连续多章都有海报文案式独段；
- 为建立辨识度硬塞固定口头禅；
- 同一记忆锚再次出现但意义完全没变，只是在提醒读者；
- 为制造名场面破坏人物逻辑、世界规则或因果。

### Arc级要求

若本章是Arc收束章，必须额外确认本Arc已自然留下：
- 一个可复述场面锚；
- 一个主要人物强性格瞬间；
- 一个可继续回响的物件/关系/台词/行为锚；
- 一句普通读者能说清的阶段变化。

不足时优先回看Arc结构，不允许只在最后一章硬补。

## 13. Chapter Title Review（硬门）

读取 `quality/CHAPTER_TITLE_STANDARD.md`。

最终章节名必须回答：
1. 去掉章号后，标题单独看有没有阅读欲？
2. 它指向本章真正的核心冲突/选择/意象，还是只是在概括“发生了什么”？
3. 读到章末后，标题是否获得第二层意义、回收或更具体的重量？若没有第二层，也必须至少有明确冲突/反常识张力。
4. 是否泄露正文尚未确认的死亡、身份、谜底、因果？
5. 与最近5章是否出现同构流程句式？

### 默认REWRITE

- 纯事件摘要，例如“少了一个人以后”“人回来了”“再验一次”；
- 直接使用Rolling Outline/Scene Card内部功能名；
- 连续使用“先…… / 又…… / 一……”等流程式结构却没有双关/冲突收益；
- 普通道具名与正文核心无第二层关系；
- 必须由作者额外解释才显得“有深意”；
- 靠剧透关键答案制造点击。

### 版本绑定

**最终标题属于Candidate字节的一部分。**

标题改动后：
- candidate SHA必然变化；
- 旧Post-Draft / Publication / Payoff / Continuity / Final Delivery绑定全部失效；
- 必须重新绑定最终标题版本并重新跑exact-head CI。

CH010的标题修订即作为标准案例：正文不变，`少了一个人以后` → `这笔账得有人认`，并重新完成全部版本绑定和CI。

## 14. 结论

只允许：
- PASS：可以进入Expectation/Payoff Gate；
- REWRITE：退回DRAFTED或SCENE_READY；
- BLOCKED：关键资料/审计缺失。

**Publication PASS后仍禁止交用户。最终交稿权限只由FINAL_DELIVERY_GATE + WORKFLOW=USER_REVIEW决定。**
