# PUBLICATION GATE V1

> 目标：在连续性正确之外，强制判断正文是否像真实可发布的长篇小说。任何硬 FAIL 都必须重写，不得带病交稿。

## 1. Scene First

正文不得直接从 Rolling Outline 展开。必须先经过 `quality/SCENE_CARD_TEMPLATE.md`，把后台任务翻译成人物世界内部的场景。

Scene Card 中不得出现 CHxxx、FP-xxx、KNOWS/UNKNOWN、Canon、Ledger、State Diff、必须推进等后台标签。

## 2. 后台泄漏硬 FAIL

正文出现以下内容，默认 FAIL：
- “第三章 / 上一章 / 前文 / 本章”等作者章节回指；
- CHxxx、FP-xxx、CHAR-xxx、Canon、Ledger、Snapshot、State Diff 等仓库语言；
- 角色用只有作者数据库才知道的标签思考。

正确做法：改为人物世界内部记忆、器物、动作或现场证据，例如“上次在西院时”或直接回忆当时的触感。

## 3. 段落硬门

- 常规叙事段优先 2—5 句，承载完整动作链 / 观察链 / 心理链。
- 一句独段只用于真正需要停顿的死亡、反转、答案、极强动作节点或关键对话。
- 连续出现 3 个以上一句式叙述段，默认 FAIL，除非处于明确的极端节奏场景。
- “红。白。黑。”“不能。太弱。到他了。”这类短词连续独段，默认视为短视频/AI脚本感。

## 4. 提纲扩写硬 FAIL

若一章呈现为“样本A→结果、样本B→结果、样本C→结果、主角最后通关”，或明显逐项兑现大纲清单，默认 FAIL。

普通样本只保留对场景真正有戏剧价值的 1—2 个，其余压缩进连续叙事。章节必须由人物欲望、阻力、选择、后果推动。

## 5. 胜利算法检查

每章检查最近 5 章的高层破局模型，而不只检查具体手段。

以下即使换了道具也视为重复：
- 先看别人踩坑 → 得到完整规则 → 自己精准通过；
- 装弱/隐藏 → 对方误判 → 无代价脱身；
- 偷听内幕 → 获得答案 → 规避危险。

同一高层算法近期再次成为主破局方式，默认 FAIL 或必须加入明显的误判、代价和结构变化。

## 6. 正确也要付成本

陈缺判断正确可以获得主动权，但成功后至少应新增一项：身体代价、记录风险、关系债、暴露面、责任、资源消耗或新的错误认知风险。

连续两次“判断正确且主要只有收益”，默认 FAIL。

## 7. 配角主体性

重要配角进入场景前必须能回答：

> 如果陈缺今天不在场，这个人自己会做什么？

如果答案不存在，说明人物可能只是信息/异常展示器，需重构。

赵石、韩鸦、顾长槐及关键知情者不得只负责展示症状、送情报或把主角送往下一个剧情节点。

## 8. 推理语言控制

“这不能证明 / 这只能证明 / 至少说明 / 这不代表”等研究报告式限定不可成为默认叙述模板。

优先用动作表现谨慎：压下猜测、暂不行动、保留证据、选择低风险方案。整章若同类逻辑限定句反复出现，必须改写。

## 9. Reader Experience

交稿前回答：
1. 本章读者最想知道的一个主问题是什么？
2. 本章是否真正改变了这个问题，而不是只增加一条症状？
3. 情绪状态是否至少发生一次变化？
4. 是否有一个明确的小兑现，而非全靠悬念？
5. 章尾是否由本章因果自然推出下一步，而非神秘人/门响/金句式硬切？

## 10. 发布结论

最终结论只允许：
- PASS：可以作为 Candidate 交用户；
- REWRITE：小说感/节奏/人物/算法存在硬问题；
- BLOCKED：关键 Canon/资料缺失。

Continuity Gate PASS 但 Publication Gate FAIL 时，仍不得交稿。
