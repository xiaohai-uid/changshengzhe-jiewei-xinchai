# MEMORY ANCHOR SYSTEM V1

> 目的：解决“小说能追读，但读完后没有东西留下”的问题。
>
> 本系统不要求每章制造金句，也不把“名场面”当KPI。它负责识别、保护、回响和增值那些真正从人物、关系、物件与世界规则中自然长出来的记忆点。

## 一、核心区分

商业追读解决：

> 读者为什么点下一章？

记忆锚解决：

> 读者三个月后为什么还记得这本书？

二者都重要，但不能互相替代。

- `EXPECTATION/PAYOFF`：推动继续阅读。
- `MEMORY ANCHOR`：让人物、场面、关系和世界在读者脑中留下可复述痕迹。

## 二、六类记忆锚

### 1. SCENE · 场面锚

读者能复述或脑补成一幅画的场景。

标准不是“够大”，而是：具体、独特、与本书核心冲突绑定。

### 2. LINE · 台词锚

只有这个人物在这个情境下才会说出的句子。

禁止先写“金句”再找场景承载。脱离人物利益、身份和当下压力的漂亮话不是有效锚点。

### 3. BEHAVIOR · 行为锚

人物反复呈现但不机械重复的选择习惯、动作方式或处理问题的方法。

行为锚必须体现人物世界观，而不是口头禅的动作版。

### 4. OBJECT · 物件锚

在不同阶段反复出现、意义发生变化的具体物件、标记、数字或制度符号。

有效物件锚应逐步改变含义，而不是仅做一次性道具。

### 5. RELATIONSHIP · 关系锚

两个人之间可反复回响的债、承诺、误会、称呼、动作、约定或共同秘密。

关系锚的价值来自关系变化后旧东西产生新意义。

### 6. THEME · 命题锚

少量、低频、真正承载全书命题的句子或意象。

越核心越不能高频重复。重复必须伴随含义变化。

## 三、生命周期

记忆锚状态：

- `PLANTED`：第一次出现，潜力尚未确认。
- `ESTABLISHED`：已经形成明显可识别记忆。
- `ECHOED`：在新情境中再次出现，并增加情绪/关系/信息。
- `RECONTEXTUALIZED`：旧锚意义被新事实重新解释。
- `PAID_OFF`：完成主要回收。
- `RETIRED`：不再继续经营。

不得为了保持ACTIVE而强行重复。

## 四、章节级规则：必须检查，不必每章新增

每个Scene Card必须回答：

> 如果读者三个月后只记得这个场景一样东西，最可能是什么？

允许答案：

`NO NEW ANCHOR`。

但必须说明本章的主要功能，例如过渡、因果承接、资源兑现、关系推进。禁止为了通过检查硬塞一句金句、一个怪癖或一个象征物。

每章Post-Draft必须检查：

1. 本章是否自然产生了新的Anchor Candidate？
2. 是否调用了已有ACTIVE/ESTABLISHED锚？
3. 若回响已有锚，意义是否增加/改变？
4. 是否存在“作者强行提醒读者记住”的写法？
5. 是否为了显得深刻而堆哲理句、口头禅、象征物？

## 五、Arc级硬要求

单章不强制名场面；**Arc结束时必须审计整体记忆残余。**

每个Arc结束前至少应自然形成：

1. **一个可复述场面锚**；
2. **一个主要人物的强性格瞬间**；
3. **一个可在后文继续回响的物件 / 关系 / 台词 / 行为锚**；
4. **一句普通读者能说清的阶段变化**：例如“这一段结束后，陈缺从被分拣的药材变成了白骨山开始主动使用的人”。

如果Arc结束时四项均弱，不允许只靠结尾补一场大戏；应检查整个Arc是否缺乏人物选择、关系变化和具体残余。

## 六、记忆增值规则

好的回响不是复制。

有效回响至少满足一项：

- 同一句话换了说话人，意义改变；
- 同一物件从威胁变成筹码/纪念/债；
- 同一动作在不同权力关系下产生相反意义；
- 早期笑话后来成为痛点或承诺；
- 早期世界观句子被后续真相重新解释；
- 配角曾经的普通习惯在重大选择时成为识别标志。

无效回响：

- 原句机械再说一次；
- 为提醒读者而硬插回忆；
- 相同象征重复出现但意义不变；
- 角色突然开始固定口头禅；
- 每个高潮都重复同一命题句。

## 七、人物声音与记忆

重要人物不要求“每人一句名言”，但应逐渐形成可识别的：

- 关注点；
- 回避方式；
- 说话长度；
- 价值判断；
- 面对压力时的选择模式。

判断问题：

> 隐去姓名后，这句关键对白/这个关键选择是否仍有较大概率只属于这个人物？

若所有聪明角色都说同一种完整、冷静、逻辑严密的话，人物记忆度不足。

## 八、防止过度设计

以下情况直接视为风险：

- 连续多章都有“像海报文案”的句子；
- 人物为了金句停止自然说话；
- 每个角色都被分配固定口头禅；
- 强行让一个小物件在没有因果必要时频繁出现；
- 通过粗体、独段、反复强调逼读者记住；
- 为制造名场面破坏人物逻辑或世界规则。

原则：

> **先让事情值得记，再让系统负责不忘。**

## 九、Ledger规则

权威记录：`tracking/MEMORY_ANCHOR_LEDGER.md`。

每条至少记录：

- Anchor ID；
- 类型；
- 首次出现章节；
- 所属人物/关系/势力；
- 当前意义；
- 当前状态；
- 最近一次回响；
- 下一次允许回响的“条件”而不是固定章数；
- 可能的最终回收方向；
- 过度使用风险。

Candidate阶段只能提出 `ANCHOR DIFF PROPOSAL`，不得直接把新锚写成正式Ledger事实。

只有用户确认并Canon Promotion后，才更新正式Ledger。

## 十、维护节奏

### 每章

- Scene Card回答记忆候选问题；
- Post-Draft做Memory Anchor Audit；
- Rule Coverage检查MEM类Rule ID。

### 每5章

- 与Canon Snapshot一起回顾最近5章：
  - 新增哪些锚；
  - 哪些只是一次性细节，不值得继续；
  - 哪些锚开始过度使用；
  - 哪些人物仍缺可识别声音/行为。

### 每个Arc

执行Arc Memory Audit，检查“四项硬要求”。

### 每卷

选择少量真正进入读者长期记忆的核心锚继续跨卷，其余允许PAID_OFF/RETIRED。禁止所有小细节都变成长线伏笔。

## 十一、与其他系统的关系

- Canon：决定锚点是否真的发生过。
- Plot Ledger：记录剧情用途；Memory Ledger记录读者记忆用途。两者可重叠但不等同。
- Expectation/Payoff：负责追读；Memory Anchor负责回忆与辨识。
- Style：防止金句腔、口号化与机械重复。
- Publication Gate：判断Anchor是否自然、人物专属、可复述。
- Final Delivery：只确认该检查确实执行，不要求每章必须新建锚。

核心原则：

> **不是每章都要成为名场面；但一部长篇不能写到最后只剩“剧情发生过”。**
